# A3 Ubuntu 24.04 VPS 验收设计

## 背景

A1/A2 已完成本地脚本、安装安全边界、Serv00 兼容和 sing-box 配置迁移测试。A3 的目标是把这些结论放到一台用户明确提供的 Ubuntu 24.04 测试 VPS 上验证，不把测试机当成生产节点改造。

## 验收目标

1. 确认 VPS 操作系统、架构、磁盘、内存、SSH、现有 sing-box 服务和监听端口，并把结果写成不含 Token、UUID、私钥或完整订阅 URL 的基线。
2. 从本仓库 A3 分支准备的固定内容执行项目级安装/更新路径；如果机器已有非本项目服务或无法安全识别的状态，只做只读检查并停止，不强行覆盖。
3. 使用真实 sing-box 二进制执行配置 `check`，验证 systemd 服务、健康检查 timer、配置权限和监听端口。
4. 只在确认配置已备份且服务正常后，注入一个临时无效配置，验证重启防护拒绝坏配置并恢复原配置；测试结束必须复原服务和配置。
5. 记录命令、退出码、摘要和恢复结果，远程输出脱敏后再提交到 A3 分支。

## 安全边界

- 不删除 `/etc/s-box`、`/root`、用户目录或防火墙全局链。
- 不执行 `rm -rf`、`iptables -F`、`nft flush ruleset`、整机重装或关闭 SSH。
- 不在日志、提交或最终回复中保存 VPS 密码、Token、UUID、私钥、完整配置或完整订阅 URL。
- 测试失败时优先恢复原配置和服务；若恢复失败，保留诊断材料并停止后续变更。

## 成功标准

- 基线采集成功，且脱敏报告可复核。
- `sing-box check -c /etc/s-box/sb.json` 成功（或报告机器当前实际配置路径）。
- `systemctl is-active sing-box`、健康 timer 和预期监听端口通过。
- 故障注入被拒绝，坏配置未成为运行配置，恢复后的配置摘要与注入前一致。
- 测试结束 SSH 可继续使用，非项目防火墙规则没有被修改。
